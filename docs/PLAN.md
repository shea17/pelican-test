# 《鹈鹕测试》· The Pelican Test — 制作计划

一支约 2:17 的代码动画短片。鹈鹕骑自行车，沿一条连续的路穿过 20 个时代，每过一道画框换一种画风。
全片画面与声音均由代码生成，不使用任何外部图片、影片、音频素材。

- 交付：① 浏览器预览页（实时 Web Audio + 播放控制条）② 成片 MP4（1920×1080）
- 环境：Node 22.22.2 · 浏览器执行体 Microsoft Edge（本机唯一的 Chromium，由 `CHROME_PATH` 解析指过去）·
  ffmpeg 9.0.2 full build（winget 安装，含 libx264 / aac，工具里显式解析路径，不依赖 PATH）
- 代码许可：MIT（本项目自有代码）；影片本身保留所有权利
- 参考仓库仅作**思路**参照，不复制其代码、影片、音频、美术简报文字、构图与笑点

## 1. 时间轴（唯一事实来源，`src/beat/timeline.js`）

120 BPM → 1 拍 = 0.5 s，1 小节 = 4 拍 = 2.0 s。

拍点原点：**t₀ = 1.0 s**（0–1 s 是纸张质感的无拍引子）。此后所有小节线落在 `1 + 2n` 秒上，
于是 `5, 11, 17, …, 125` 全部是**小节正拍**——20 个版块边界与 Outro 起点无一例外踩在强拍上。

| 段 | 区间 (s) | 小节数 | 说明 |
|---|---|---|---|
| 引子 | 0 – 1.0 | — | 纸张、尘埃、静场 |
| Intro | 1.0 – 5.0 | 2 | 两条字幕；第二条落在 4.0 s（小节内第 3 拍，强拍） |
| 版块 1–20 | 5.0 – 125.0 | 每块 3 | 边界 5, 11, 17, …, 125 |
| Outro | 125.0 – 137.0 | 6 | 7×3 展墙 + 空席位 |
| 合计 | **137.0 s = 2:17** | | |

版块 k 的区间：`t0 = 5 + 6(k−1)`，`t1 = 11 + 6(k−1)`。

| # | 名称 | 年代 | t0–t1 |
|---|---|---|---|
| 1 | 撒哈拉岩画 | 约前 4000 | 5–11 |
| 2 | 埃及壁画 | 约前 1300 | 11–17 |
| 3 | 汉画像石拓片 | 约 100 | 17–23 |

**版块内三小节**（u = t − t0）：

| 小节 | u | 内容 |
|---|---|---|
| 1 | 0 – 2 | 穿框进场、路面与景别建立、标题卡在第 3 拍落位 |
| 2 | 2 – 4 | 这一版的梗 / 高光；可整体 `timeScale` 降到 0.15 做定格 |
| 3 | 4 – 6 | 加速骑向下一道画框，u = 6 时正好穿框 |

**脚踏**：一圈 = 2 拍 = 1.0 s。全片 137 圈，相位与全片拍点同源，任何版块都不重新起拍。
踏频由拍点给（`crank = π · beats`），车轮由**齿比**给（默认 2.2:1），地面标线按车轮真实线速度滚动，
远景按视差系数滚动——三者分别可调，避免"轮子在打滑"。

## 2. 空间与镜头

- **作画空间**：每个版块一张 1000×1000 单位画板。
- **取景窗**：16:9，宽度 620–1000 单位可推可拉，默认 1000 宽（= 562.5 高），映射到 1920×1080，
  即满幅时 1 单位 = 1.92 px、推到最近时 1 单位 = 3.10 px。
  垂直方向可在 1000 单位内摇移（宋代山水靠这个：先看巨峰，再摇下去找鹈鹕），水平方向随路推进。
- **鹈鹕尺寸**：车轮半径 52，整车高约 135、长 200。默认景别下占画面宽约 20%，
  特写时收紧取景窗到 620 宽。这个比例是刻意的：它是"山水里的一个小人"，不是广告片主角。
- **穿框**：画框是一块立在路上的实体边框（不是屏幕边框）。随镜头推进由小及大，
  在强拍那一帧正好掠过镜头、内沿撑满画面；框内是下一版块，框外是上一版块（canvas clip 实现）。
  穿框同时叠一次镜头推近（+6% 焦距，120 ms，缓出）。

## 4. 骨骼木偶（`src/rig`）

同一套姿势喂给 20 个风格自己的绘制函数，换风格时动作不断线。

- **自行车**：两轮（前轮可转向）、车架（菱形 / 弯梁可切换）、车把、坐垫、牙盘、链条、脚踏。
  参数：轴距、轮径、车架色、齿比。车轮辐条数可调（木轮 8 根、公路车 32 根、皮影 4 根）。
- **鹈鹕**：髋、膝、踝、蹼足（两点 IK 踩踏板）、脊柱三节、颈（四节样条）、头、喙（上喙 + 喉囊）、
  翼（三节，可当"手"用）、尾。参数：体型胖瘦、颈长、喙长、喉囊下垂度、羽毛密度。
- **输出**：`pose(t, opt) → {bike:{…}, bird:{…}, contact:{…}}`，纯数据，单位是版块本地坐标。
- **姿势库**：`ride`（默认）、`poseProfile`（埃及正面肩侧面头）、`glide`（唐/宋飘带）、`whiteEye`（八大）、
  `shadowOnly`（诺斯费拉图）、`lissajous`（示波器扭形）、`pixelHop`（8-bit 起跳）、`selfie`（竖屏）。
- **风格适配层**：`drawPose2D`（笔触）、`drawPoseSilhouette`（拓片/皮影剪影）、`drawPoseLine`（白描/矢量）、
  `drawPosePixel`（像素栅格化）、`drawPoseShadow`（投影）。风格文件只挑适配器，不重写骨骼。

**标题卡（已定：融入构图，位置每块自定）**

埃及放象形文字框、汉画放题记、浮世绘放题签、8-bit 放 HUD、聊天窗放标题栏、代码段放注释块。
融进画面容易好看，也容易看不见，所以配三条硬约束，每块都要在接触表上逐条验收：

1. 1080p 下最小字号 ≥ 34 px（≈ 17.7 单位）；中文名、英文名、年代三者都要过线。
2. 文字与紧邻背景的对比 ≥ 4.5:1；不达标就补同材质底衬（石面、纸面、扫描线遮罩），底衬本身也算构图。
3. 完整落在画面 8% 安全边距内，且被主体或运动元素遮挡不得超过 0.5 秒。

不达标就退回重排，不接受"这块正好被鹈鹕挡住了"。

## 6. 共用水墨套件（版块 3/4/5/6/9）

一套渲染底座，五种笔法：

- 底座：宣纸纤维纹理（程序生成 + 缓存）、墨色浓淡（多层 alpha 叠加）、飞白（笔压衰减 + 速度断笔）、
  晕染（多次低 alpha 扩散）、界尺直线（清明上河图的建筑）。
- 3 拓片：黑底白线，反向取值 + 石面颗粒 + 边缘剥蚀。
- 4 白描：纯线，无填充，线宽随速度变化，飘带用样条。
- 5 山水：皴法（披麻/斧劈）笔刷组 + 远近墨色分层 + 云雾留白。
- 6 界画：直尺线 + 淡彩层 + 人物点缀。
- 9 写意：极简三笔 + 大面积留白 + 一枚朱印。

## 8. 声音

同一段原创主旋律贯穿全片，每个版块换成该时代/地域的乐器，全部 Web Audio 程序合成。

- **共用图**：`audio/score.js` 导出一个纯函数 `build(ctx, {from, to})`，只用振荡器、噪声、滤波器、
  包络和程序生成的卷积混响 IR。实时播放与离线渲染走**同一份代码**，保证对拍一致。
- **乐器**：撒哈拉手鼓/人声吟唱、埃及竖琴、汉编钟、唐琵琶、宋古琴、清上河笛+锣鼓、玛雅陶笛+木鼓、
  莫卧儿西塔+塔布拉、八大箫、皮影甘美兰、浮世绘三味线、星月夜/呐喊弦乐（呐喊段走调尖叫）、
  默片钢琴+管风琴、示波器正弦+电子管嗡鸣、8-bit 双方波+三角波+噪声、MIDI 铃声、短视频流行节拍、
  代码段钢琴+合成器。车铃与链条声作贯穿打击乐。
- **蒸汽波（18）** 按规格做"放慢的商场磁带"：先合成 151.2 BPM、比主调高 4 个半音的原创 smooth jazz，
  再当磁带处理（playbackRate 0.7937、3–5 s 大混响、4 kHz 低通、0.5 Hz 摇晃、磁带底噪），
  进/出段做磁带减速与加速，第 2 小节做 3–4 次跳针。
- **Outro**：各年代乐器齐奏，推镜时渐弱，最后一拍只剩车铃。

## 9. 渲染管线

- 页面：`public/index.html`，p5 + p5.brush 以经典脚本载入，`src/main` 为 ES module。
  `window.renderAt(t)` 是纯函数入口：给定 t，画面唯一确定。
- 逐帧：Puppeteer 打开页面 → `renderAt(t)` → 截图 PNG。多进程并行 worker。
- 音频：`OfflineAudioContext(2, 137×48000, 48000)` → WAV。
- 合成：ffmpeg 9.0.2（libx264 / aac，H.264 高质量 + 响度归一到 −14 LUFS）。
- 检查工具：单帧 `shot`、接触表 `sheet`（浏览器里拼图后截图，零原生依赖）、fps 对比脚本。
- **fps 决策（已实测）**：同一段横向平移样片，30fps 单帧 116.9 ms、60fps 单帧 116.4 ms——
  瓶颈是 Puppeteer 截图而非绘制，所以 60fps 的代价约等于帧数翻倍，而不是每帧更贵。
  **正片 60fps，日常迭代 30fps**。实测 6 进程吞吐 41 帧/秒（30fps 全片 100 秒渲完）。详见 `docs/RENDER_NOTES.md`。
- **复古量化**：皮影、8-bit、聊天动图三格内部时间量化到 8–12 Hz（镜头运动不量化）。

## 14. 空间语法重写：从"二十幅画"到"一卷长卷"（2026-10-24）

何朴指出衔接方式错了：不该是"每块一张静止的画 + 结尾穿框"，而应是
**二十段并排成一条长卷，镜头持续右移，鹈鹕在卷上骑，画风在接缝处换**。已按此重写。

新的几何：

- 每段在长卷上宽 **1800** 单位；取景窗 **1000** 单位（1 单位仍 = 1.92 px）；骑手固定在画面 **42%**。
- 镜头左边缘 = 骑手世界坐标 − 0.42 × 取景宽；每段 6 秒走 1800 单位 = 300 单位/秒，全程匀速。
- 任何一个时刻，画面里最多一条接缝：先是左边的接缝扫出（约 1.4 s），
  接着 **2.67 秒的纯段落**（p 0.233–0.678，梗就落在这里），最后右边的接缝扫入（约 1.9 s）。
- 接缝扫到骑手身上时，正好是强拍，也正是画风切换的瞬间——中间的"隔水"竖带把它挡住。

渲染方式：接缝在画面里时，先画另一段（不画骑手）并拍快照，再画骑手所在段，
最后在 2D 覆盖层上贴快照、按接缝位置 clearRect 掉骑手那一侧。骑手永远只由当前段绘制，
所以左边是旧笔法、右边是新笔法，而中间那一条竖带负责遮住换笔的瞬间。

代价：接缝在画面里的时候要画两段，单帧成本约 1.7 倍；全片从 100 秒涨到 110 秒渲完。

## 15. 接缝处的骑手连续性（2026-10-24）

改法：`drawPanel` 让**每一段都用同一个世界坐标、同一套姿势画同一只鸟**，只是各段自己的笔法。
`pose(t, dist)` 是纯函数，所以两半的轮子、车架、身体在像素上严格对齐；
遮罩沿接缝切开后，左半是旧笔法、右半是新笔法，中间由"隔水"竖带盖住换笔的那一瞬。

为此取消了两处会破坏连续性的设定：

- 宋代原先靠把骑手缩到 0.34 制造"渺小"，缩放不同会让左右两半大小对不上。
  现在**骑手永远 1:1**，渺小感改由镜头给（取景窗 1400→560，山体加高到 560）。
- 竖屏的 9:16 视口从"屏幕正中"移到"画面 42%"，与骑手在长卷上的位置对齐；骑手按 1.92 画，
  正好等于世界单位到像素的比例，于是与相邻段的鸟接得上。

接缝带宽 26 → 19 世界单位（约 73 px）。

## 17. 阶段 4：声音（2026-10-24）

配乐是**程序化合成**的，没有采样、没有第三方音源：`tools/music.mjs` 直接算出 48k 立体声 WAV。

### 为什么能咬住画面

所有事件都由 `src/beat/timeline.js` 推出来，不是手工对轨：

- 120 BPM → 一拍 0.5 s，一小节 2 s；每块 6 s = 三小节，和声一小节换一个。
- 每块三和弦从 `PROG[k]` 里取，围绕 A 小调，但每块调式不同（唐用 A–D–E， Scream 用半音簇，代码用五度）。
- 每个接缝前 0.18 s 有一声"换笔"的噪声扫频——就是画面里那条缝扫过的那一下。

### 二十种音色

四件合成器（拨弦 / FM 钟 / 气声笛 / 带蜂鸣的弹拨）+ 铺垫 + 低音 + 四种打击，
按 `TONE[k]` 每块配不同的组合：撒哈拉是笛与手鼓，汉是石磬，唐是筝，皮影开场一记锣，
八大只剩一声，星夜是钢片琴琶音，示波器是两个纯音，聊天是消息提示，代码是打字机。

另有一条贯穿全片的自行车声：花鼓的细碎咔哒按轮速 7.5 Hz 调制，音量压得很低（-26 dB 左右），
只在安静处才听得见——它不是音效，是"这只鸟一直在骑"的底噪。

### 交付

`out/pelican-test-final.mp4`：1920×1080 / 30fps / 137.000 s / AAC 48k 立体声 / -16.3 LUFS。
`out/score.wav`：137.6 s 母版（尾巴留 0.6 s 让最后一下自然衰减）。

## 18. 阶段 5：打磨（2026-10-24）

### 先量，再改

`tools/perf.mjs` 给 `window.draw` 套一层计时，逐块取单帧成本。改之前平均 **43.2 ms/帧**：

| 最贵 | ms |
|---|---|
| 12 星月夜 | 129.8 |
| 03 汉画像石 | 97.9 |
| 05 宋代山水 | 90.2 |
| 04 唐白描 | 64.9 |
| 14 诺斯费拉图 | 55.0 |

### 一个失败的优化，记下来

我把 `speckle()` 从"每颗一个 `circle()`"改成"一次 `beginShape(TRIANGLES)` 画上千个方点"，
以为能把上千次绘制调用压成一次。**结果慢了 15%**：汉从 98 → 136，诺斯从 55 → 86。

p5 2.x 的 WEBGL immediate 模式按顶点收的税，比它内部那个复用的圆几何还重。
教训：在 p5 里，"合并 draw call"不等于"更快"，得实测。已回退。

### 真正有效的

- 颗粒数量砍到原来的四成，半径放大一点——观感几乎不变，成本线性下降。
- 星夜的笔触 620 → 400，麦田 340 → 220。
- 宋代的扫描线从每 1 单位一行改成每 2 单位（`scanRows(pts, 2)`），山体填充少一半调用。

结果：平均 **43.2 → 39.2 ms**（星夜 130→103，汉 98→95，宋 90→75，埃及 51→40）。
离 30 fps 还差一点，但这是**构建时间**，不是成片质量——成片照样是 30 fps 的 4110 帧。

### 画面

- **汉画像石的马**重画了。原来是两匹马叠成一团、腿细如铁丝；现在一辆车一匹马，
  躯干+颈+头用"先全填、再描边、再填一遍"的并集轮廓合成，腿改成有粗细变化的实体。
- 汉的人群加了高矮与手势差别；标题卡挪开，不再压住下方的边框。

### 没做完的

- 唐白描的脸：只有指甲盖大，加了五官也读不出来，要改得把人物整体放大。
- 清明上河图仍是一排房子，缺河道与纵深。
- 浮世绘的松树还是扇形。
- 星夜仍是全片最贵的一块（103 ms），真要提速得把静态背景烘成贴图，那是另一套架构。
